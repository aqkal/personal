Most portfolios are a scroll. I wanted mine to be a place.

So this site boots into a stylized 3D night scene inspired by my actual campus: the University of Queensland's sandstone Great Court, jacarandas in bloom, street lamps along the paths, and the Brisbane river wrapping the whole thing with the city lights across the water. You walk around as a small student character. My internships are office towers you approach, my projects are arcade cabinets (one of them is secretly playable), and my skills grow in a garden.

## The stack

- **Next.js 16** (App Router) with **TypeScript** and **Tailwind CSS v4**
- **Three.js** via **React Three Fiber** for the world, with bloom and vignette postprocessing
- **Zod-validated content model**: one set of typed files feeds the 3D world, the classic HTML pages, and the resume
- Deploys to **both Vercel and Cloudflare Workers** from the same codebase

## One source of truth

The core architectural decision: content lives in typed TypeScript files, and everything renders from them. Adding a job to my resume spawns a building in the world:

```ts
export const experience: Experience[] = [
  {
    id: "dsr-branding",
    company: "DSR Branding",
    role: "Web Development Intern",
    start: "2025-05",
    end: null,
    // ...highlights, tech
    world: {
      zone: "career",
      dialog: ["DSR Branding - my current internship!"],
    },
  },
];
```

The world layout maps each entry to an anchor point in its zone, gives it a door, an interaction radius, and a label. The classic `/experience` page maps the same array to cards. Nothing is duplicated, so nothing can drift out of sync.

## Keeping it smooth

A portfolio that lags is a portfolio that gets closed. The rules I set:

- Three.js loads **only** after you choose Game mode; the landing page and classic pages ship zero game code
- Trees, lamps, and skyline towers are **instanced** (a handful of draw calls for hundreds of objects)
- Per-frame data lives in refs and module state, never in React state
- A quality ladder watches the frame rate and steps down resolution, then effects, before anything stutters
- Software renderers (no GPU) are detected up front and get a floor-quality scene instead of a slideshow

## What's next
